# Kiosk screen publishing v1

The user requested a connected developer → cloud → operator → smart kiosk publishing flow. Extend the existing JavaScript Phygital feature with a server-side KioskX client, leaving Unity/game authentication untouched. The additive API is part of the pending JavaScript 5.9.0 release.

The cloud owns machine authorization, durable revision checks and publication state. Operator web and Flutter edit the same contract. ZHZN Android 9+ launches third-party content in a separate process and WebView data directory, with no native interfaces, cookies or device permissions. Do not widen the privileged storefront's iframe policy. No new third-party dependencies.

The first release supports one HTTPS display URL and optional controller URL per machine. Application-owned session state stays at the developer's origin. Mapping delivery is not playback confirmation, reward verification, or automatic conversion of mobile binaries. Runtime availability is explicit through experiencePlayerV1. Releasing the SDK independently cannot enable older cabinets.
